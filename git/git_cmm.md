 チーム開発 Git 運用メモ
 repo: internship-2026-team-a
 前提: リポジトリ・メンバー・各自のブランチは作成済み
 方針: 各自のブランチで実装 → PR → main に反映
================================================================

----------------------------------------------------------------
■ 毎日 最初に打つコマンド
----------------------------------------------------------------
git status                  # 前日の残り変更がないか確認
git switch main
git pull origin main        # main を最新にする
git switch murata           # 自分のブランチへ（各自の名前）
git merge main              # main の最新を自分のブランチに取り込む

  → コンフリクトが出たら解消 → git add <file> → git commit
  → その後 git push しておく


----------------------------------------------------------------
■ 作業中（区切りごとに繰り返す）
----------------------------------------------------------------
git status
git add <file>
git commit -m "add: 〇〇機能を実装"


----------------------------------------------------------------
■ 毎日 最後に打つコマンド
----------------------------------------------------------------
git status                  # 未コミットの変更がないか
git add <file>
git commit -m "add: 〇〇を実装"
git push origin murata      # 必ず push して残す（PC 故障・共有対策）

  ※ 初回だけ  git push -u origin murata
     以降は    git push  だけでよい


----------------------------------------------------------------
■ 機能が完成したら（main へ反映）
----------------------------------------------------------------
git switch main && git pull origin main
git switch murata && git merge main     # 最新 main を取り込んでおく
git push

→ GitHub で PR 作成（base: main ← compare: murata）
   ・変更内容と動作確認したことを書く
   ・Reviewers にメンバーを指定

→ 指摘対応は同じブランチに commit + push（PR は自動更新される）
→ マージ後:
     git switch main
     git pull origin main


----------------------------------------------------------------
■ ルール
----------------------------------------------------------------
・main に直接 commit / push しない。必ず PR 経由。
・main はローカルで編集しない（pull して参照するだけ）。
・push 済みの履歴は書き換えない（push --force は使わない）。
・作業前に必ず git branch --show-current で自分のブランチを確認。


----------------------------------------------------------------
■ 自分のブランチだけで使うファイル（共有したくないもの）
----------------------------------------------------------------
▼ 自分だけ無視する（チームに影響しない・推奨）
   .git/info/exclude に書く。このファイルは Git 管理外。
     my_memo.txt
     sandbox/
     tmp_*.py

   PowerShell で追記:
     Add-Content .git/info/exclude "my_memo.txt"

▼ チーム共通で無視する
   .gitignore に書いてコミット（node_modules/ .env *.log .vscode/ など）

▼ 注意
   ・.env などの秘密情報は絶対にコミットしない。
   ・すでにコミット済みのファイルは ignore が効かない:
       git rm --cached <file>    # 追跡だけ外す（ファイルは残る）

▼ 確認
   git status --ignored
   git check-ignore -v my_memo.txt


----------------------------------------------------------------
■ 困ったとき
----------------------------------------------------------------
git restore <file>          # 変更を破棄して元に戻す  
git restore --staged <file>  # add を取り消す     git stash / git stash pop    # 変更を一時退避／復元
git merge --abort            # マージをやめて元に戻す
git log --oneline --graph --all
git reflog                   # 操作履歴（消したと思った状態を復元）
