# 機能ページ 中身仕様（全案共通）

12機能ページそれぞれの「何を置くか」を定義する。**見た目のトーンは各案の `PROMPT.md` が決め、
中身の要素はこのファイルが決める**。どの案で作っても情報構造は同じになる。

全ページ共通で `DESIGN_RULES.md` の絶対ルール（1画面完結・リスト3件前後・
ハンバーガー格納・日時管理常時表示・CSSクラス1つでの開閉）が適用される。

---

## 共通の骨格

すべての機能ページは、トップページと**同じシェル（ヘッダー／ナビ／ハンバーガー）を再利用**し、
本文領域だけを差し替える。ナビの現在地（`.on`）を該当機能に移すこと。

本文は次の3行グリッドで組む。

```
┌ ページヘッダ  … ページ名 + 件数サマリー + 主要アクション1つ（auto）
├ フィルタ/切替  … 必要なページのみ。タブ or セグメント（auto）
└ 本体          … 一覧・ボード・フォーム（minmax(0,1fr) で残り高さを吸収）
```

- **主要アクションは1ページ1つ**。それ以外は本体内の行アクションに置く
- 一覧の常時表示は 3〜5行。あふれは「`＋ 他 N件`」ではなくページ内の件数表示に留め、
  行数上限は CSS（`nth-of-type`）で担保する
- **戻り導線**: ページヘッダのページ名の左に「`← ダッシュボード`」を置く

## 1. ダッシュボード `/`

各案の `index.html` が完成形。新規作成しない。

## 2. 受信箱の一元化 `/inbox`

| 領域 | 内容 |
|---|---|
| ページヘッダ | 「受信箱」／`要対応 4件・未読 12件・今週 98通を自動分類` ／アクション「一括既読」 |
| フィルタ | セグメント: `要対応(4) / 面接日程(3) / 選考結果(2) / スカウト(6) / その他` |
| 本体（左） | メール一覧 5行。各行 = `分類タグ + 件名 + 企業名・時刻`。未読は件名を太字 |
| 本体（右） | 選択中メールのプレビュー。差出人・本文冒頭3行・抽出情報（日程候補・締切日）・「タスクに追加」「カレンダーに登録」ボタン |

- 分類タグの色は `DESIGN_RULES.md` の意味づけ表に従う（面接日程=`--danger`／要返信=`--warn`／結果=`--ok`）
- 複数アカウント（Gmail / iCloud）由来を小さなラベルで示す。**一元化されていることが伝わる要素**

## 3. メール自動振り分け `/mail-filter`

| 領域 | 内容 |
|---|---|
| ページヘッダ | 「メール自動振り分け」／`ルール 6件・今週 98通を分類・誤分類 2件` ／アクション「＋ ルールを追加」 |
| 本体（左） | ルール一覧 5行。各行 = `分類先タグ + 条件の要約（件名に「面接」を含む 等） + 今週の適用数 + ON/OFFトグル` |
| 本体（右） | 分類結果のサマリー: カテゴリ別の件数を横棒グラフで5本 ＋ 「最近の分類結果」3行（誤分類には「修正」リンク） |

- 中間発表では機械的なキーワード判定の仮実装。**AI 学習にデータを使わない設定である旨**を画面内に一行明示する
- 誤分類の修正操作が存在することを見せる（学習の入口として発表で説明できる）

## 4. 通知 `/notifications`（中間発表対象外。仕様のみ）

| 領域 | 内容 |
|---|---|
| ページヘッダ | 「通知」／`重要メール 2件・停滞企業 1社` ／アクション「すべて既読」 |
| 本体（動作①） | **重要メール検知の通知**。メールを取り込んだ際 `category = "重要"` のメールがあれば、画面上部にバナー表示する（例：「重要なメールが2件あります」）。バナークリックで受信箱（`/inbox`）の該当メールへジャンプする |
| 本体（動作②） | **音沙汰なし企業の検出**。`is_watched = true`（登録企業）のうち、最後にメールを受信した日から一定日数（既定 14日）経過している企業を検出する。`GET /api/notifications` のようなAPIで「停滞中の企業リスト」を返す想定 |

- 動作①は受信箱（メール自動振り分け機能）が確定させた `category` の値をそのまま使う。**新しい分類ロジックはここでは作らない**
- 動作②は選考ステータス管理ボード（機能7 `/pipeline`）と組み合わせて使う想定。該当企業のカードに「⚠️ 2週間音沙汰なし」のようなバッジを表示する。単体（このページだけ）では動作②は完結しない
- 「一定日数（既定14日）」は仕様として固定値に置く（設定画面で変更可能にする機能は今回定義しない）
- `docs/spec.md`「やらないこと（今回対象外）」に明記の通り、中間発表では通知の配信ロジック・APIともに実装しない。パネル項目は `href="#"` のまま、サブテキストのみ表示する

## 5. カレンダー・日程調整 `/calendar` ★中間発表スコープ

| 領域 | 内容 |
|---|---|
| ページヘッダ | 「カレンダー」／`今週の面接 3件・ゼミと重複 1件` ／アクション「＋ 予定を追加」 |
| フィルタ | 表示切替セグメント `週 / 月`（既定は週）＋ 凡例（就活=ブランド色／学業=グレー／締切=警告色） |
| 本体（左） | 週ビュー。7列 × 時間帯行（9:00〜21:00を3hごと5行程度に圧縮）。予定は色付きブロック |
| 本体（右） | ①**重複アラート**: 「7/30 15:00 面接 と 10:30 ゼミ が同日」等 1〜2件、②未回答の日程調整 2件（候補日ボタン3つ + 「この日で返信」） |

- **学業（ゼミ・講義・課題）と就活の予定を色で必ず分ける**。この分離がこのページの価値
- メールから抽出した日程候補をワンクリックで登録できる導線を右カラムに置く

| フィルタ | セグメント: `今日 / 今週 / すべて / 完了`（既定は今日） |

## 7. 選考ステータス管理 `/pipeline`

| 領域 | 内容 |
|---|---|
| ページヘッダ | 「選考ステータス」／`24社・選考中 18社・内定 1社` ／アクション「＋ 企業を追加」 |
| 本体 | 5列カンバン `気になる(6) / エントリー(5) / 書類選考(7) / 面接(5) / 最終・内定(1)`。各列カード2〜3枚＋「＋ 他 N社」 |

- カードは `企業名 + 状態タグ（ES 本日 / 今日 15:00 / 結果待ち 5日 / 内定）`。
  左端の色帯で緊急度（当日=`--danger`／3日以内=`--warn`）
- カードは企業詳細へのハブ。**カード内に想定問答・メール履歴・メモへの小リンクを持たせる**
- 案04ではこのページがトップと同一構造になる。トップと重複するので案04では
  「企業一覧テーブル表示」の切替セグメントを追加して差分をつける
