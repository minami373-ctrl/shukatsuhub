# 案03 「今日やること」集中型

企画案のゴール（**情報整理の手間を最小化し、浮いた時間を研究に充てる**）を最も直接的に画面化した案。

## コンセプト

**「開いたら、今日の動きだけが分かる」**。上部タブは `今日 / カレンダー / 受信箱` の3つに固定。
残り9機能は右から出るパネル（`☰ 機能`）に格納する。

ヒーローに「**研究にあてられる時間 3.5h**」を出すのが特徴。就活タスクを減らすと研究時間が増える、
というペルソナの動機に直結する指標をトップに置いている。

## 画面構成（PC・スクロールなし）

```
┌──────────────────────────────────────────┐
│ ShukatsuHub [今日] カレンダー 受信箱4 ☰機能 (佐)│
├──────────────────────────────────────────┤
│ ╔══════════════════════════════════════╗│
│ ║7/30(木)                研究3.5h タスク5件║│ ← ヒーロー（横並び）
│ ║今日やることは5件。まずES提出から。予定3件 メール4通║│
│ ╚══════════════════════════════════════╝│
│ ┌─ ✓今日やること ────┐┌─ ▣今日のタイムライン ─┐│
│ │□ ES提出     最優先 ││10:30 ゼミ            ││
│ │□ 日程回答   要返信 ││13:00 空き2h→ES提出   ││
│ │□ 想定問答   準備   ││15:00 一次面接        ││
```

## 1画面完結の作り

- ヒーローは縦積みをやめ、見出しとサマリー4指標を**横並び**（`flex` + `flex-wrap`）にして高さを圧縮
- `.two` の2カラムは `minmax(0,1fr)` で残り高さを吸収。リストは常時4件まで＋「＋他1件」
- **スマホ**：サマリーは2指標まで、右カラムのタイムラインを上下2段に組み替え、「今日返すメール」カードは非表示（受信箱タブから見る）

## 遷移設計

| 階層 | 手段 | 対象 |
|---|---|---|
| 常設タブ | 上部3タブ | 今日（ホーム）／カレンダー／受信箱 |
| 常時表示 | タイムライン・タスク・メール | 各行クリックで詳細へ |
| パネル | `☰ 機能` | 残り9機能。各項目に現況の一言（「充実度 68%」「新着 5件」）付き |

パネル項目にサブテキストを出すことで、**開かずに状況が分かる = 開く回数が減る**設計にしている。

## 長所

- 「何をすればいいか」が一目で決まる。隙間時間のスマホ確認に最も強い
- タブ3つなので、機能が20個になっても上部は変わらない
- タイムラインの「空き 2h ← ES 提出をここに」は発表でのインパクトが大きい

## 短所

- 選考の全体像（何社受けているか）はトップから見えない
- 「今日」の情報しかないので、中長期の計画には別ページが必要

## 実装メモ

- 「研究にあてられる時間」= 可処分時間 − 予定 − 就活タスク見積り。中間発表時点では固定値でも成立する
- パネルは `body.nav-open` の付け外しのみ（`translateX(100%) → none`）
- タイムラインは1日を時間スロットの配列で持ち、空きスロットに「締切が最も近いタスク」を差し込む
